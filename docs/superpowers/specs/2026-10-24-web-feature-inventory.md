# Web (index.html) feature inventory vs iOS port

Sources: /c/tmp/shift_ro/index.html (1314 lines, read fully), /c/tmp/shift_ro/ios/Shift/** (all Swift files), ShiftTests (names only).
Legend: iOS status ✅ same / ⚠️ partial or different / ❌ missing. Value: Essential / Useful / Questionable.
Notation: "mobile" = web viewport < 640px (useMobile, L96-100). Line refs are index.html.

## Global rules that many rows depend on (web)
- Date strings are `yyyy-MM-dd`; `resolveEndDate` (L56-62): allDay or no times -> `ed||sd`; endTime "24:00" -> `ed||sd`; `endTime<=startTime` -> startDate+1; else `ed` if `ed>=sd` else `sd`.
- `calcWorkHours` (L72-79): mins = end-start (+1440 if <=0, "24:00" = 24h); break = 60 if mins>480, 45 if mins>360, else 0; hours = (mins-break)/60 (rounded to minute-level). null for allDay / missing times. `fmtHours` (L80): `Xh` or `XhYm`, "-" for null.
- Summaries (week/month/sidebar) group by COLOR (first event title seen for that color is the label), count an event only on its START date, skip events whose workHours is null/0 (i.e. all-day events never count).
- Color filter (`checkedColors`, empty = all) only filters the summary lists, NOT what is drawn on the calendar.
- Only `confirm()` in the app is the 回収 confirmation (L1141). No alert(), no tooltips/title attributes, no delete confirmation.

## iOS-only problems found while reading
1. **Month overflow clipped silently** (MonthView.weekRow `.clipped()`, fixed `numH=22`, `barH=14`): on a 6-week month a row is roughly 50-60pt, i.e. only ~1-2 bars are visible; any further simultaneous events (very common with night+day shifts) disappear with no "+N" indicator. Web grows the row instead.
2. **Filter hides events on the calendar** (Store.visibleEvents used by MonthView/WeekView/SpanLayout and totals): web only filters summaries. Active filter + no on-screen explanation (only the filled filter icon) -> user thinks shifts vanished.
3. **No locale/localization set**: project.yml has no `CFBundleDevelopmentRegion`/localizations and views never set `.environment(\.locale, ja_JP)`. On an English device the system DatePicker (month/day format), ColorPicker, 完了/Cancel standard buttons, confirmationDialog Cancel, fileImporter UI and `%d` formatting follow the device language, mixing English with Japanese labels. Weekday labels/titles are hard-coded Japanese so they are fine.
4. **Tiny fixed fonts, no Dynamic Type**: week block title 8pt/time 7pt, month bars 9pt, holiday names 7pt, hour labels 8pt (all `.system(size:)`); below readable size, and time label in week blocks disappears below 28pt height.
5. **Month bar label for timed events shows only `startTime`** (EventBar L10), no title and no end time; two different shifts starting at 09:00 are indistinguishable (web desktop shows title, mobile shows timeLabel). Continuation segments repeat the label (web shows "...").
6. **White text on tinted colors**: EventBar/week blocks use white text on e.g. amber #f59e0b / cyan #06b6d4 at 8-9pt -> low contrast (web uses colored text on a 16% tint for bars, white only on week blocks).
7. **Accent not dark-mode aware**: Theme.accent #4f46e5 used in both modes (web switches to #818cf8 in dark).
8. **Summary in month mode uses the anchor week**: `showSummary == 1` in month view shows the week of `anchor` (a day that may be arbitrary, e.g. the 31st after paging) — misleading in month view; and in week view `月計` shows month totals whereas web shows nothing. SummaryBar also shows `計 0h` and no `データなし` when empty, and omits the color's title.
9. **Header add button places on `anchor`** (RootView.addEvent(on: anchor)) rather than creating an unplaced event; anchor is "today" at launch but any past/future day after navigation -> accidental placement.
10. **Drop targets lack feedback**: Month/Week dropDestination have no `isTargeted`; all-day row in week view and the unplaced chip area are not drop targets; dropping an already-unplaced chip on the back-zone moves it to the end of the list.
11. **Week header tap creates an event** and the all-day row's blank area does not (inverse of web); the swipe `simultaneousGesture` is attached to the whole calendar region and may fight with long-press drag/scroll (not verified at runtime).
12. **EventEditor edge cases**: `Int(breakText)` silently falls back to the default on invalid text; break larger than total gives negative hours (web identical); `canSave` trims `.whitespaces` only; opening an unplaced event shows `start = Date()` (now) rather than a normalized noon but is harmless; no `リセット` for the break override.
13. **Persistence failures swallowed**: Store.persist ignores encode/write errors (`try?`), and a single malformed event in events.json makes the whole file be treated as corrupt (moved aside, app starts empty).
14. **UnplacedArea takes fixed 120pt + header** on every screen; on small phones with the 2-row header and 6-week month this leaves ~300pt for the calendar (it is collapsible and persisted, but default is expanded).
15. **Holiday names in month cells** (7pt, always shown) crowd the 1-line cell header; the web hides them on mobile.
16. **Tests** cover Rules, SpanLayout, Store, Holidays (no UI tests); nothing covers MonthView overflow, filter-vs-display, or summary placement.
