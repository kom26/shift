# 共有カレンダー(レイヤー方式)設計

アカウント同期([2026-11-04-account-sync-design.md](2026-11-04-account-sync-design.md))の上に作る。保存先は Firebase(Auth + Firestore)。将来の Android・Web 対応を見据えて Firebase を選ぶ。

## 目的

他のユーザーと予定を共有する。予定を**レイヤー**に分けて管理し、共有はレイヤー単位で行う。共有カレンダーでは、参加者のレイヤーを重ねて表示する。

## 決まっていること

- 予定は**複数のレイヤー**に入れられる(例: 自分の予定、サークル、旅行計画)。
  - 標準で「自分の予定」レイヤーがある(削除・名前変更はできない)。レイヤーを選んでいない予定は、ここに入る。
  - 通常予定は、必ずどれか 1 つのレイヤーに入る(最後の 1 つは外せない)。
  - 勤務予定は、職場がレイヤーを兼ねる(外せない)。レイヤーの選択には職場以外が出る。勤務予定は、いつも「自分の予定」にも入る。
  - 保存は予定の `layerIds`(nil・空は「自分の予定」)。古い予定の移行は不要。
- 絞り込みは「通常予定」「職場」「予定レイヤー」の 3 つのくくり。職場側とレイヤー側の両方に合う予定だけを出す。
- 共有はレイヤー単位。共有するときに、**レイヤーごと**に「見るだけ」か「編集もできる」かを選ぶ。
- **共有カレンダー**は、複数のユーザーが参加する入れ物。参加者が自分のレイヤーを出し合い、重ねて表示する。
- 共有カレンダーの中に**新しいレイヤーを作れる**。そのレイヤーの予定は、参加者全員が作成・編集できる。
- 共有カレンダーへの招待は**招待リンク**で行う。
- 給料に関する情報は共有しない。
- 職場の予定は、**職場名と色**だけ見せる。どの職場の予定かは分かるが、それ以外の職場の情報は見せない。

## 用語

| 用語 | 意味 |
|---|---|
| レイヤー | 予定を分類する単位。名前と色を持つ。持ち主がいる |
| 自分のレイヤー | 自分が作ったレイヤー。標準では自分だけが見られる |
| 共有カレンダー | 参加者が集まって、レイヤーを重ねて見る場所 |
| 共有レイヤー | 共有カレンダーの中で作ったレイヤー。持ち主は共有カレンダー。全員が編集できる |

## 見せる範囲

共有した予定で、他の参加者に見える項目と見えない項目を分ける。

| 見える | 見えない |
|---|---|
| タイトル、日付、開始・終了時刻、終日かどうか | 時給、日給、交通費、深夜・曜日・一律の加給、調整給 |
| レイヤー名、レイヤーの色 | 見込み給与、給料日、給料日の詳細 |
| 職場名、職場の色 | 休憩、実労働の時間(給料の計算に使う値) |
| | メモ |
| | 職場のほかの設定(時給、締め日など) |

メモは、見せる範囲に選ばれなかったので、標準では見せない。見せたい場合は、あとから項目を足す。

## データ構造(Firestore の案)

アカウント同期の構造に、レイヤーと共有を足す。

```
users/{uid}/
  layers/{layerId}        自分のレイヤー(名前、色、並び)
  events/{eventId}        予定の全項目(給料の項目を含む。自分だけが読める)
  workplaces/{id}         職場の全項目(自分だけが読める)
  ...(アカウント同期の仕様どおり)

calendars/{calendarId}
  name, ownerUid, createdAt
  members/{uid}           { role: owner | member, joinedAt }
  invites/{token}         { createdBy, expiresAt, revoked }
  layers/{layerId}        共有カレンダーのレイヤー { name, color, source }
                           source: 「共有カレンダー自身のレイヤー」か
                                   「ユーザー uid の自分のレイヤー(権限: view | edit)」
  events/{eventId}        共有される予定の**公開できる項目だけ**
                           { layerId, title, date, endDate, start, end, allDay,
                             workplaceName, workplaceColor, updatedAt, deleted }
```

### 給料の情報を守る方法

- 予定の全項目(給料の項目を含む)は `users/{uid}/events` にだけ置き、本人しか読めないルールにする。
- 共有する予定は、公開できる項目だけを `calendars/{calendarId}/events` にコピーして置く。コピーは、元の予定を変更したときに自動で更新する。
- こうすることで、アプリの表示を間違えても、給料の情報が他人の端末に届くことはない。
- 共有カレンダーの中で作ったレイヤーの予定は、最初から公開できる項目だけで作る。給料の項目は持たない。

### 権限のルール(Firestore Security Rules)

- `calendars/{id}` と、その下のデータは、`members` に入っているユーザーだけが読める。
- 予定の書き込みは、次のどちらかのときだけ許可する。
  - その予定のレイヤーが「共有カレンダー自身のレイヤー」である。
  - その予定のレイヤーの持ち主が自分で、そのレイヤーを共有に出している。
- 「見るだけ」で共有されたレイヤーの予定は、持ち主以外は書き込めない。
- 招待リンクの参加は、有効期限内で、無効化されていない `invites` があるときだけ許可する。

## 画面のイメージ

- カレンダーの切り替えは、左上のハンバーガーから開くドロワーで行う(設定の歯車はドロワーの中へ移した)。「自分のカレンダー」と、参加している共有カレンダーが並び、「レイヤーの管理」「設定」もここにある。
- 共有カレンダーでは、レイヤーごとに表示のオン・オフができる。
- 予定を作るときは、入れるレイヤーを選ぶ。共有カレンダーでは、編集できるレイヤーだけが選べる。
- 自分のレイヤーを共有カレンダーに出す操作は、レイヤーの設定画面から行う。そこで「見るだけ」か「編集もできる」かを選ぶ。
- 招待リンクは、共有カレンダーの設定画面で作る。リンクの無効化と、参加者の削除もそこで行う。

## 既存機能への影響

- 予定にレイヤーを持たせる。既存の予定は、移行時に「自分の予定」レイヤーに入れる。
- 未配置エリア、週計・月計、ウィジェット、アラームは、自分のカレンダーの予定だけを対象にする。共有カレンダーの予定は、これらに含めない(最初の版)。
- 給料の計算、給料日アイコン、見込み給与の詳細は、自分の予定だけが対象。共有カレンダーの他人の予定は、給料に関わらない。
- 重複(ダブルブッキング)の注意は、最初の版では自分の予定だけで判定する。

## 未決定

- 招待リンクを開くための仕組み。iOS のユニバーサルリンクには、ドメイン直下にファイルを置く必要がある。GitHub Pages のプロジェクトページ(`kom26.github.io/shift/`)では置けないため、別の置き場所(Firebase Hosting など)が要る。
- 共有カレンダーの中で他人が作った予定に、職場を付けられるか。付けるなら、誰の職場を参照するか。
- 共有カレンダーの参加人数の上限。
- 参加者を抜けたとき、その人のレイヤーの予定をどうするか(そのまま残す、消す)。
- 共有カレンダーでの通知(予定が追加されたときなど)。
- 無料で足りる範囲に収まるかの試算(読み書きの回数が、共有で増える)。

## 進め方

1. アカウント同期を、**予定ごとの同期とレイヤーを含む形**で作る(ここは共有の前提になる)。
2. 共有カレンダーの作成・参加・表示を作る。
3. レイヤーを共有に出す機能と、見せる範囲の制限を作る。
4. 招待リンクを作る。

各段階で CI(無料)を確認する。Codemagic のビルドは、まとまった変更が揃ってから指示があったときだけ起動する。

## 範囲外(最初の版)

- 共有カレンダーでの通知。
- 共有カレンダーの予定を、週計・月計・ウィジェット・アラームに含めること。
- コメントや返信など、予定へのやり取りの機能。
