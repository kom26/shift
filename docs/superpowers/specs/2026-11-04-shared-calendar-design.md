# 共有カレンダー設計

アカウント同期([2026-11-04-account-sync-design.md](2026-11-04-account-sync-design.md))の上に作る。保存先は Firebase(Auth + Firestore)。将来の Android・Web 対応を見据えて Firebase を選ぶ。

## 目的

他のユーザーと予定を共有する。友達同士で予定を見せ合う、コンカフェなどの出勤予定を、見る人にだけ届ける、といった使い方を想定する。

## 予定の分類(2026-11-05 に変更)

レイヤーはやめて、**ラベル**に統一した。

- 勤務予定は職場でまとまる。ラベルは付けない。
- 通常予定は、ラベルを 1 つだけ付けられる。付けなければ「ラベルなし」(グレー)。
- 予定の色は、既定では職場・ラベルの色に付いていく。「個別カラー」をオンにした予定だけ、その予定の色になる。
- 色の並びは、グレーが先頭。
- 絞り込みは「勤務予定(職場ごと)」と「通常予定(ラベルごと)」の 2 つのくくり。くくりをタップすると中身がまとめて選ばれる。
- 予定の編集画面の「職場」「ラベル」の行をタップすると、下から選択シートが出る。シートの「編集」を押すと、行のタップが名前・色の編集になり、右端に並べ替えが出る。
- 保存は予定の `labelId`(nil は「ラベルなし」)と `ownColor`。古いデータの `layerIds` は、通常予定の最初の 1 つをラベルに引き継ぐ(勤務予定のレイヤーは外れる)。

## 共有カレンダー(2026-11-05 に変更)

共有する単位は、**職場とラベル**。

### 作成する人が決めること

1. カレンダー名
2. 相手に見える自分の名前(共有者名)
3. 共有する項目(職場・ラベルから選ぶ)
4. 種類
   - **見せるだけ**: 自分の予定を、招待した相手が見るだけ。相手は何も共有しない(出勤予定をお客さんに見せる、など)。
   - **相互に共有**: 参加した全員が、自分の予定を見せ合う(友達同士)。
5. 作成 → 招待を送る

### 招待

- 招待は、**QR コード**か**招待リンク**。QR は画像として保存できる。
- リンクを開いたとき、アプリが入っていればアプリが開く。入っていなければ、TestFlight の招待リンク(https://testflight.apple.com/join/wwsStTJA)に移る。
- 招待コードの貼り付けは、リンクを開けないときの予備として残す。

### 見せ方と編集(2026-11-05 に決定)

- 共有カレンダーは、参加者の予定を**重ねて見る**だけの場所。相手の予定は、**編集できない**。
- 共有カレンダーの**中で作った予定**は、参加者全員が相互に編集できる(給料の項目は持たない)。
- 「見せるだけ」のカレンダーでは、参加者の名前を持ち主に見せる。
- 持ち主は**許可制**にもできる。許可制のときは、参加を申し込んだ人が「承認待ち」になり、持ち主が承認するまで予定を見られない。持ち主は、見ている人を削除することもできる。

### 招待を受けた人

- **見せるだけ**: 共有者名の入力だけで参加できる(相手に見せるものは無い)。
- **相互に共有**: 作成者と同じく、相手に見える自分の名前と、共有する職場・ラベルを選んで参加する。

## 見せる範囲

共有した予定で、他の参加者に見える項目と見えない項目を分ける。

| 見える | 見えない |
|---|---|
| タイトル、日付、開始・終了時刻、終日かどうか | 時給、日給、交通費、深夜・曜日・一律の加給、調整給 |
| ラベル名と色、職場名と色 | 見込み給与、給料日、給料日の詳細 |
| 共有者名 | 休憩、実労働の時間(給料の計算に使う値) |
| | メモ |
| | 職場のほかの設定(時給、締め日など) |

メモは、標準では見せない。見せたい場合は、あとから項目を足す。

## データ構造(Firestore の案)

```
users/{uid}/
  labels/{labelId}        自分のラベル(名前、色、並び)
  events/{eventId}        予定の全項目(給料の項目を含む。自分だけが読める)
  workplaces/{id}         職場の全項目(自分だけが読める)
  calendars/{calendarId}  参加している共有カレンダーの控え { name, ownerUid, kind }
  ...(アカウント同期の仕様どおり)

calendars/{calendarId}
  name, ownerUid, kind: oneway | mutual, requireApproval: bool, createdAt
  members/{uid}           { role: owner | member, status: active | pending, displayName, joinedAt, sharedKeys: [...] }
                           sharedKeys: 共有に出している職場・ラベル("w:<id>" / "l:<id>")
  invites/{token}         { createdBy, expiresAt, revoked }
  events/{eventId}        共有される予定の**公開できる項目だけ**
                           { ownerUid, sourceKey, title, date, endDate, start, end, allDay,
                             name, color(職場名・ラベル名と色), updatedAt, deleted }
```

### 給料の情報を守る方法

- 予定の全項目(給料の項目を含む)は `users/{uid}/events` にだけ置き、本人しか読めないルールにする。
- 共有する予定は、公開できる項目だけを `calendars/{calendarId}/events` にコピーして置く。元の予定を変更したときと、共有する項目を変えたときに、自動で更新する。
- こうすることで、アプリの表示を間違えても、給料の情報が他人の端末に届くことはない。

### 権限のルール(Firestore Security Rules)

- `calendars/{id}` と、その下のデータは、`members` に入っているユーザーだけが読める。
- 予定のコピーを書けるのは、`ownerUid` が自分のものだけ。
- 見せるだけのカレンダーでは、参加者(持ち主以外)の予定は共有されない。
- 共有カレンダーの中で作った予定(`sourceKey` が `calendar`)は、参加している全員が書ける。
- 許可制のカレンダーでは、参加の申し込みは `status: pending` で作られ、持ち主が `active` にするまで、予定を読めない。
- 持ち主は、見ている人(参加者)を削除できる。許可制のカレンダーでも、承認後の参加者を削除できる。
- 招待での参加は、有効期限内で、無効化されていない `invites` があるときだけ許可する。

## 招待リンクの仕組み

- Firebase Hosting(無料枠)に、次の 2 つを置く。
  - `/.well-known/apple-app-site-association`(ユニバーサルリンク用)
  - `/join/<コード>` のページ。アプリが入っていれば、リンクを開いた時点でアプリが開く。入っていないときだけ、このページが表示され、TestFlight の招待リンクに移す。
- アプリに Associated Domains(`applinks:<Hosting のドメイン>`)を足す。
- QR コードは、同じリンクを画像にしたもの。

## 画面のイメージ

- カレンダーの切り替えは、左上のハンバーガーから開くドロワーで行う。「自分のカレンダー」と、参加している共有カレンダーが並ぶ。
- 共有カレンダーを開くと、参加者ごと・項目ごとの表示のオン・オフができる。
- 招待は、共有カレンダーの設定画面で、QR とリンクを出す。リンクの無効化と、参加者の削除もそこで行う。

## 既存機能への影響

- 未配置エリア、週計・月計、ウィジェット、アラームは、自分のカレンダーの予定だけを対象にする。共有カレンダーの予定は、これらに含めない(最初の版)。
- 給料の計算、給料日アイコン、見込み給与の詳細は、自分の予定だけが対象。
- 重複(ダブルブッキング)の注意は、最初の版では自分の予定だけで判定する。

## 未決定

- 参加人数の上限。
- 参加者が抜けたとき、その人の予定をどうするか(そのまま残す、消す)。
- 共有カレンダーでの通知。
- 無料で足りる範囲に収まるかの試算(読み書きの回数が、共有で増える)。

## 進め方

1. 【済】アカウント同期を、予定ごとの同期とラベルを含む形で作る。
2. 【済】共有カレンダーの作成・参加・退出(招待コード)。
3. 作成画面を、名前・共有者名・共有する項目・種類・許可制を選ぶ形にする(承認待ちの扱いを含む)。
4. 予定のコピーを共有カレンダーに載せ、参加者の予定を重ねて表示する。
5. 招待リンクと QR(Firebase Hosting、Associated Domains、TestFlight への案内ページ)。

各段階で CI(無料)を確認する。Codemagic のビルドは、まとまった変更が揃ってから指示があったときだけ起動する。

## 範囲外(最初の版)

- 共有カレンダーでの通知。
- 共有カレンダーの予定を、週計・月計・ウィジェット・アラームに含めること。
- コメントや返信など、予定へのやり取りの機能。
