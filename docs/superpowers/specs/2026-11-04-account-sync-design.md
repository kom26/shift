# アカウント同期(Firebase)設計

iCloud 同期を廃止し、Apple / Google でログインして Firebase に保存する。iOS 版と Web 版(https://kom26.github.io/shift/)で同じデータを使う。

## 決まっていること

- 保存先は Firebase(Auth + Firestore)。Supabase は採用しない(オフライン対応が最初からあるため)。
- ログイン方法は Apple でサインインと Google でサインインのみ。
- ログインは任意。ログインしなくても今までどおり端末内だけで使える。
- 同期は予定ごと(1 件ずつ)。競合は項目ごとの「最後に変更した時刻」が新しいほうが勝つ。
- 初回ログイン時に端末とアカウントの両方にデータがあるときは、どちらを残すかを選んでもらう。
- iCloud 同期(`CloudSync`)は廃止する。

## データ構造(Firestore)

`users/{uid}/` の下に、種類ごとのコレクションを置く。

| コレクション | 内容 |
|---|---|
| events | 予定(未配置を含む) |
| workplaces | 職場(時給・日給・締め日・給料日など) |
| favorites | よく使う予定 |
| anniversaries | 記念日・誕生日 |
| settings | 週の始まりなど、端末をまたいで共有する設定(1 件) |

- 各データに `updatedAt`(最後に変更した時刻)と `deleted`(削除済みの印)を持たせる。削除は印を付けるだけにする。そうしないと、別の端末で消した予定が復活する。
- アラームなど端末ごとの状態は同期しない。
- 1 件が Firestore の 1MB 上限に近づくことはない(メモは長くても数 KB)。

## アプリ側の動き

- 端末にも保存し続ける。オフラインでも動き、つながったら差分だけを送る(Firestore のオフラインキャッシュを使う)。
- 変更は 1 件ずつ即座に送る。他の端末の変更はリアルタイムで受け取る。
- 新しい端末でログインしたときは、データが届くまで「引き継ぎ中」画面を出す(`RestoringOverlay` を流用)。時間切れで進める必要はなくなる。
- ログアウトしても端末のデータは消さない。別のアカウントでログインし直したときは、初回ログインと同じ扱いにする。

## 初回ログイン時

| 端末 | アカウント | 動き |
|---|---|---|
| データなし | データあり | アカウントのデータを取り込む |
| データあり | データなし | 端末のデータをアカウントへ送る |
| データあり | データあり | 「この端末のデータ」か「アカウントのデータ」を選んでもらう。選ばなかったほうは消える |
| データなし | データなし | 何もしない |

## 設定画面

「データのバックアップ」を「アカウント」に変える。ログイン / ログアウト、最後の同期の時刻、アカウント削除(App Store の規約で必須)を置く。

## iOS の実装

- Firebase iOS SDK を Swift Package Manager で追加する。Auth と Firestore のみ。
- `Store` の保存のたびに呼ばれる `onLocalChange` を、1 件ずつの送信に置き換える。
- 既存の `SyncSnapshot` は初回ログイン時の取り込みに使い、そのあとは使わない。
- Apple でサインインは `AuthenticationServices`、Google でサインインは Google Sign-In SDK を使う。
- `project.yml` に capability(Sign in with Apple)と URL スキーム(Google)を足す。

## Web の実装

- Firebase の CDN 版(modular SDK)を `index.html` から読み込む。ビルド手順は増やさない。
- Apple でサインインは `OAuthProvider('apple.com')` のポップアップを使う。
- 許可ドメインに `kom26.github.io` を登録する。
- 保存先の `localStorage` はそのまま残し、ログインしたときだけ同期する。

## Web 版に足りない機能

iOS 版にあって Web 版に見当たらない機能。Web の `index.html` を実際に確認した結果を、実装前にこの表で最終確認する。

| 機能 | Web の現状 |
|---|---|
| 職場・時給・見込み給与・給料日 | なし(「給料日」「交通費」「深夜」が 0 件) |
| 日給、曜日加給、一律加給・調整給 | なし |
| よく使う予定 | なし |
| 予定の重複(ダブルブッキング)の注意 | なし |
| アラーム | なし(Web では実現できないため対象外) |
| ウィジェット | なし(Web では実現できないため対象外) |
| 記念日・誕生日 | 文字列はあるが、iOS の機能とは別物の可能性が高い。要確認 |
| 祝日 | 取得処理はある。表示の有無は要確認 |
| 予定バーの文字サイズ調整 | なし |

給料まわりが最も大きい。職場の登録から始まり、見込み給与の計算(`PayCalculator` 相当)、給料日の判定(`PayCycle` 相当)、給料日アイコンと詳細まで、iOS のコアロジックを JavaScript に移すことになる。計算の仕様は iOS のテストを正とし、同じ入力で同じ金額になることをテストで確かめる。

## 進め方

1. **ユーザー作業:** Firebase プロジェクトを作り、Apple / Google のログインを有効にする。Apple 側で Web 用の識別子とキーを作る。設定値(iOS 用の `GoogleService-Info.plist`、Web 用の設定オブジェクト)を共有してもらう。
2. **iOS:** ログインと同期を実装し、iCloud 同期を外す。
3. **Web:** ログインと同期を実装する。
4. **Web の機能追加:** 給料まわりから順に足す。

各段階で CI(無料)を確認する。Codemagic のビルドは、まとまった変更が揃ってから指示があったときだけ起動する。

## 範囲外

- 家族や友人との予定の共有。
- Android 版。
- Apple / Google 以外のログイン方法。
